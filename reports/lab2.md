# lab2 实验报告（ch4：地址空间）


## 功能总结

本章的核心工作是给 mmap/munmap 建一套完整的惰性分配（lazy allocation）链路：`sys_mmap` 只做参数校验并在地址空间里"登记"一段 vpn 范围与权限（不分配任何物理帧），真正的分配推迟到首次访问触发缺页时——trap_handler 读出 stval，交给 `handle_page_fault` 过三道关（落在登记区内、权限匹配、该页尚未分配）后补帧建映射，再原样带回 sepc 重执行出错指令。munmap 采用"区间精确匹配"语义：start/len 都须页对齐且与某个已登记区完全重合才释放，只归还 `data_frames` 里真正分配过的帧（惰性区大部分页从未映射，直接遍历整个 vpn_range 去 unmap 会在 `PageTable::unmap` 的 assert 上崩掉）。

另外两项是把 ch3 的 sys_trace、sys_get_time 按虚存语义重写：内核不再直接解引用用户指针（ch3 全是物理地址所以没事，ch4 这样写内核自己就 PageFault），统一走带映射与权限检查的 `translated_byte_buffer_checked` 翻译后再读写——包括"翻译失败返回 None 而不是 unwrap 打崩内核"和"PTE 的 V/R/W 位逐一校验"。syscall 计数也从 ch3 移植了过来（TCB 的 `syscall_times` 数组 + 分发入口统计），因为评测的 ch4 期望清单包含 ch3_trace 的输出。分层上最大的收获是体会到"syscall 层管参数合法性、memory_set 层管空间冲突"各司其职后，每层代码都变得很短。

## 问答题

### 1. SV39 页表项的组成与标志位作用

64 位 PTE 按位拆分：`[63:54]` 保留；`[53:10]` 是 44 位物理页号 PPN；`[10:0]` 是标志位，共 8 个：

- **V**（valid）：该表项有效。中间层表项与叶子表项都靠它表示"这级指向的东西存在"；本次调试里 munmap 后的页就停在"叶子 PTE 被清零但树还在"的状态，软件查表必须自己检查 V 位，否则会拿着 ppn=0 去访问物理地址 0x0。
- **R / W / X**：读/写/执行。注意编码不正交：R=0 且 W=1 是**保留编码**，硬件对它读、写、取指全部 PageFault——`ch4_mmap2` 的 prot=2 正是靠这一点被杀的。
- **U**：用户态可访问。U=0 的页内核可用、用户态一碰就 fault，是特权隔离的硬件基础。
- **G**（global）：多地址空间共享的映射（如内核跳板页）可打 G 位避免换 satp 时被 TLB 冲掉。
- **A / D**：访问位/脏位，硬件访问时置位，供淘汰算法参考（本次在打点输出里能直接看到 A 位被 QEMU 置上）。

### 2. 缺页的表现与关键寄存器

访问的页面不在页表中、PTE 无效（V=0）、或权限不符（U 态碰 U=0 的页、只读页上写等），MMU 都会以缺页形式陷入内核。对应的异常是 scause 里的 **InstructionPageFault(3) / LoadPageFault(5) / StorePageFault(7)** 三兄弟——具体哪一个由访问类型决定：取指、load、store。

关键寄存器与 ch3 的异常处置一脉相承：**scause** 给出异常原因（决定走哪个分支、需要什么权限——本次实现的 trap_handler 正是靠拆分 Load/Store 两个臂来告知 handle_page_fault 该查 R 还是 W）；**stval** 存出错的虚拟地址，是缺页处理的核心输入（`VirtAddr::from(stval).floor()` 直接得到待补帧的 vpn）；**sepc** 是触发异常的指令地址，缺页处理成功后不动它、原样 `trap_return`，CPU 就会重新执行那条指令——"异常返回后重执行"是惰性分配能成立的机制基础。

### 3. Lazy 策略

**好处**：分配推迟到真正访问的那一刻，mmap 立即返回；按需消耗物理帧，申请量远大于使用量的进程不浪费内存（编译器声明大数组、语言运行时预留堆等都是这种模式）；进程创建也不用等整块地址空间建好页表。

**10G 申请、只用 1M 的页表开销估算**：10GiB ≈ 2.6M 个页，SV39 每张表页 512 项，叶子表约需 2.6M/512 ≈ 5000 页 ≈ **20MiB**（中间两级再加约 10 页，量级不变）。若非惰性，这 20MiB 页表加上登记工作在 mmap 时就得付出；惰性实现下只用到的 1M（256 页）才会逐页建立映射，页表开销也随之降到 KiB 量级。页表元数据本身也占内存——这正是惰性策略连页表都要省的原因。

**实现思路**（即本次的做法）：mmap 时只在 MemorySet 里登记 vpn 区间与权限，不碰页表；访问时硬件缺页 → trap_handler 读 stval → 内核查登记区：落在某区间内、权限包含本次访问所需（load 查 R、store 查 W）、且该 vpn 尚未分配过 → 分配物理帧、写入叶子 PTE → sepc 不动返回用户态重执行。权限不符或不在任何登记区则杀死进程；"已分配仍缺页"也要拒绝——那是 W-only 保留编码这类硬件永远不放行的组合，不拦住会陷入"补帧→fault→再补帧"的死循环。

### 4. Swap 下页面失效在 PTE 上的表现

换出页的 PTE **V 位清 0**——MMU 见 V=0 就触发缺页，与"从未映射"在硬件看来一样；区别由内核自己维护：软件可把 swap 分区中的位置（盘块号）等元数据塞进 PPN 等字段（硬件不看 V=0 项的其余位）。缺页进来后内核查自己的记录发现是"已换出"而非"未映射"，从盘上读回、重新填写 PPN 并恢复 V 位，重执行即恢复。RISC-V 的 A/D 位为选择牺牲页提供依据：A=0 的页长期未访问，优先换出。

### 5. 双页表与单页表

**单页表如何"更换页表"**：单页表模式下整个系统共用一张表，切换地址空间不再换 satp 根，而是**原地改写页表里用户区间的映射**（内核区间恒定不动）——把旧任务的用户页表项换成新任务的即可。

**如何阻止用户态访问内核页**：靠 **U 位**。内核页的 PTE 一律 U=0，U 态访问直接 PageFault，S 态不受影响。本次实验里 TrapContext 页（R|W 无 U）就是这个用法——内核读写自如，用户态碰它就被杀。

**单页表的优势**：没有 satp 切换与 TLB 冲刷，任务切换便宜；内核与用户在同一地址空间，内核访问用户缓冲区无需查表翻译；trap 进出内核**不需要跳板页**——跳板（trampoline）存在的根本原因就是双页表下"切换 satp 的瞬间，正在执行的代码必须在两张表里都可见"，单页表天然没有这个问题，trap.S 可以简单得多。

**双页表何时更换**：每次 trap 进内核（换内核 satp）与 trap_return 回用户（换用户 satp，见 `trap_return` 里把用户 token 放进 a1 跳进 `__restore`）、以及任务切换到下一个任务时。若写单页表 OS，我会选择只在**任务切换**时改写用户区映射（trap 全程不换表），这也是 KPTI 出现之前传统 x86 内核的做法——代价是内核页对所有任务可见，隔离弱于双页表。

## 调试记录：一个 16MiB 堆分配引发的内核崩溃

带新 sys_trace 跑 `ch4_trace1` 时内核崩在 `Heap allocation error, size: 16777216`——没有任何代码申请过 16MiB。定位过程（打点 + 对照实验 + dump 页表链）还原出三层机关叠加的死循环，全部实锤于打印数据：

1. **39 位截断让野地址"洗白"**：`trace_read(isize::MAX)` 的地址经 `VirtAddr::from` 截断后页号恰为 27 位全 1——**正是跳板页 TRAMPOLINE 的 vpn**，translate 命中真跳板 PTE（V|R|X），通过了全部检查。上游测例仓库甚至有一条 "0x7fff_ffff_ffff_ffff should never be accessed" 的 fix 提交，说明这个坑早有前科。
2. **`min` 把循环终点拉成 0**：end = 野地址+1 = 2^63，`VirtAddr::from(end)` 截断后为 0；`end_va.min(0) = 0` 使 start 回绕到 0，而循环条件比较的是未截断的 end——`start` 永远追不上 `end`。
3. **vpn 0 是合法映射**：用户程序 `BASE_ADDRESS = 0x0`，vpn 0 就是程序自己的代码首页（V|R|X|U），`translate(0)` 每轮都合法通过，`v.push` 每轮塞一个胖指针——**Vec 无限增长撑爆 32MiB 内核堆**，扩容到 16MiB 时失败 panic。

修复原则一句话：**start/end 必须活在同一套地址语义里**——入口处统一截断到 39 位、截断后区间倒挂（end ≤ start）直接返回 None、循环推进用 `end_va.0` 而非带符号扩展的 `.into()`。这个洞其实上游 `translated_byte_buffer` 原版就带着（它更惨，直接 unwrap panic）。另一个收获是 `sys_trace` 的语义要求"替用户访问 = 完整模拟用户态行为"：读惰性 mmap 区也要先触发补帧再读（`ch4_trace1.rs:28` 的断言专门抓这个）。
